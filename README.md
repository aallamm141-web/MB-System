# MB Store — برنامج ويندوز

نفس واجهة السيستم الحالية، بس بتشتغل كبرنامج مستقل (من غير Chrome) على جهاز واحد.

## التثبيت (من غير Node ولا أدوات)
1. **فك ضغط الملف كامل** في فولدر (مش من جوه الـ zip).
2. دوس مرتين على **install.bat** (محتاج إنترنت، بينزّل حوالي 120 MB من GitHub ويتأكد إن الملف سليم).
3. هتلاقي اختصار **MB Store** على سطح المكتب. التثبيت لمستخدمك بس، ومش محتاج صلاحيات أدمن.
- لو ظهر تحذير SmartScreen: More info ← Run anyway (البرنامج مش موقّع رقميًا).
- لو التحميل فشل أو قطع: شغّل install.bat تاني.
- للإزالة: **uninstall.bat** (بيشيل البرنامج بس، والبيانات والنسخ بتفضل).
- لتحديث نسخة `install.bat` يدويًا: فك الملف الجديد وشغّل install.bat تاني (البيانات مش بتتأثر). الأفضل تنتقل لنسخة Setup.exe المتحدّثة لوحدها (تحت).

## لو هتبني بنفسك
1. نزّل Node.js 22 LTS من nodejs.org.
2. افتح PowerShell جوه الفولدر:
   - `npm install`
   - `npm start`            ← تجربة البرنامج
   - `npm run test:e2e`     ← اختبارات شاملة على البرنامج الحقيقي
   - `npm run dist`         ← بيطلّع `dist\MB-Store-Setup-1.0.0.exe`
3. (اختياري) رفع الفولدر على GitHub وتشغيل Workflow "Build Windows installer" بيبني الـ EXE في السحابة.

## فين البيانات؟  (مهم)
- **البيانات:** `%APPDATA%\MB Store`  (جوه تخزين البرنامج). **ماتغيّرش اسم الفولدر ده ولا اسم "MB Store" في الكود** — البيانات مربوطة بيه.
- **النسخ الاحتياطي:** `Documents\MB Store Backups`  (ملف لكل يوم، آخر 30 يوم) — تقدر تغيّر المكان من الإعدادات.
- لو حذفت البرنامج (Uninstall) البيانات والنسخ **بتفضل**.

## نقل بياناتك من النسخة اللي على المتصفح
1. في النسخة القديمة: الإعدادات ← 💾 تنزيل نسخة الآن. احتفظ بالملف في مكان آمن.
2. في برنامج ويندوز: الإعدادات ← "استرجاع من ملف تاني…" واختار الملف.
3. راجع الأرقام (عدد الفواتير، المنتجات، رصيد الآجل، قيمة المخزون) قبل ما تبدأ شغل. سيب النسخة القديمة زي ما هي لحد ما تتأكد.

## الطباعة
الإعدادات ← 🖨️ الطابعة: اختار طابعة الفواتير ومقاس الورق، واضغط "طباعة تجريبية". بعدها الفاتورة بتتطبع من غير نافذة.

## ملاحظات
- البرنامج بيشتغل نسخة واحدة بس (لو فتحته تاني بيرجّعك للنافذة المفتوحة).
- بيحفظ نسخة أخيرة تلقائيًا لما تقفله.

## التحديث التلقائي من GitHub (الطريقة المعتمدة)
**الفكرة:** أنت بتنزّل إصدار جديد على GitHub، والبرنامج عند العميل يفحصه لوحده، وينزّله في الخلفية، ويثبّته **لما العميل يقفل البرنامج**. بيانات العميل مش بتتلمس.

### إعداد مرة واحدة (عندك)
1. اعمل ريبو على GitHub (**Public**، أو ريبو منفصل للإصدارات بس) وارفع عليه فولدر المشروع. **ماترفعش أي بيانات محل أو نسخ احتياطية**، الريبو للكود بس.
2. في الريبو: Settings ← Actions ← General ← Workflow permissions ← **Read and write permissions**.

### كل إصدار جديد
1. عدّل الكود، وغيّر `"version"` في `package.json` (مثلاً من 1.0.0 إلى 1.0.1).
2. ارفع التعديل، وبعدين:
   `git tag v1.0.1`  ثم  `git push origin v1.0.1`  (الرقم لازم يطابق الـ version).
3. استنى حوالي 5 دقايق: GitHub بيبني `MB-Store-Setup-1.0.1.exe` وبينشر Release فيه الملف و`latest.yml`.
4. خلاص. أي عميل مثبّت بـ Setup.exe هيلاقي التحديث لوحده.

### عند العميل
- البرنامج يفحص بعد 20 ثانية من التشغيل وبعدين كل 6 ساعات. لو فيه إصدار جديد يظهر شريط: **"حمّل التحديث"** أو **"لاحقًا"** (مفيش حاجة بتتنزّل من غير موافقته).
- لو دوس "لاحقًا" الشريط يختفي 4 ساعات، لكن يفضل زرار **🔔 تحديث متاح** جنب اللوجو لحد ما يحدّث، وبيرجع الشريط عند أي تشغيل جديد.
- بعد التحميل: "التحديث جاهز، هيتثبت لما تقفل البرنامج" + زرار "ثبّته دلوقتي".
- قبل التحديث بتتعمل نسخة أمان `MB-pre-update-<من>-to-<إلى>-<تاريخ>.json` في فولدر النسخ الاحتياطي (بنحتفظ بآخر 5).
- الإعدادات ← 🔄 التحديثات: بتشوف حالة التحديث وتفحص يدويًا.

### انتقال عميل من install.bat إلى Setup.exe (مرة واحدة، وبعدها كل التحديثات من جوه البرنامج)
1. العميل مايدخلش GitHub: **إنت** تنزّل `MB-Store-Setup-x.y.z.exe` من صفحة Releases وتبعتهوله (واتساب / Drive).
2. العميل يخد نسخة احتياطية (الإعدادات ← تنزيل نسخة الآن)، وبعدين يدوس دوبل كليك على `Setup.exe` (لو ظهر SmartScreen: More info ← Run anyway). التثبيت بدون أسئلة، والبرنامج بيفتح لوحده.
3. المثبّت بيشيل لوحده بقايا نسخة `install.bat` القديمة (فولدر `resources\app`، وإلا كان هيفضل يشغّل النسخة القديمة)، فمش لازم `uninstall.bat`.
4. بياناته زي ما هي (فولدر `%APPDATA%\MB Store` ما بيتلمسش).

### قواعد عشان البيانات ما تتأثرش أبدًا
- ماتغيّرش اسم "MB Store" ولا الـ appId (`com.mb.store`) ولا origin `app://mb`.
- أي تغيير في شكل البيانات يتعمل بإضافة بس (ماتحذفش حقول). والبرنامج بيوقف الحفظ لو لقى بيانات من نسخة أحدث منه (`DATA_VER`)، بدل ما يكتب فوقها.
- جرّب الإصدار الجديد على نسخة من بياناتك قبل ما تنشره (`npm start` + استرجاع نسخة، و`npm run test:e2e`).
- لو إصدار طلع فيه مشكلة: انشر إصدار أعلى (1.0.2) بالإصلاح. البرنامج مابينزلش لإصدار أقدم تلقائي.

### مهم: ملف التثبيت الخاص بالتحديث لازم يتبني من GitHub
- لو بنيت `Setup.exe` من جهازك بـ `npm run dist` وإنت مفيش `repository` في `package.json`، الملف بيطلع **من غير عنوان الريبو جواه**، والبرنامج بيقفل التحديث التلقائي (بيظهر "التحديث التلقائي مش متاح"). ده سليم للتجربة، لكن **ماتبعتوش لعميل** عايزه يتحدّث.
- الإصدارات الحقيقية تتبني بالـ Workflow (بيظبط عنوان الريبو لوحده) كما فوق، أو تضيف `"repository"` في `package.json`.

## نسيت كلمة السر أو اسم المستخدم
- **مفتاح الاسترجاع:** بيتعمل أول ما يتعمل حساب المالك (20 حرف، يظهر مرة واحدة). بيتخزن مشفّر، والمفتاح نفسه مش بيتخزن في أي مكان. لو حساب قديم مفيهوش مفتاح، بيتعرض عليه عمل مفتاح أول ما يدخل (وكمان من الإعدادات ← الأمان).
- **لو نسي:** من شاشة الدخول "نسيت كلمة السر أو اسم المستخدم؟" ← يكتب المفتاح ← يشوف اسم المستخدم ← يختار كلمة سر جديدة. بعد الاستخدام المفتاح القديم بيتلغي ويظهر مفتاح جديد.
- **حماية:** بعد 5 محاولات غلط بيتقفل 5 دقايق.
- **الدخول بالاسم:** يقدر يدخل باسم المستخدم أو بالاسم اللي سجّله (لو مش مكرر)، بأي شكل حروف.
- **تغيير كلمة السر:** زرار 🔑 فوق (لأي مستخدم) أو من الإعدادات. والمالك يقدر يغيّر كلمة سر أي موظف من "المستخدمين ← باسورد".
- **لو ضاع المفتاح وكلمة السر معًا:** البيانات نفسها سليمة (بس مفيش دخول). الحل إن المطوّر يجهّز نسخة بيانات بدون مستخدمين، أو نضيف لاحقًا كود استرجاع موقّع منك.
